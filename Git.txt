①概念
集中式版本控制
CVS、SVN：客户端通过客户端工具从中央服务器（资源库）下载文件到本地进行更改，然后上传回资源库。但是多个人并发操作同一文件会造成文件内容失效。
VSS：客户端通过客户端工具从中央服务器（资源库）下载文件到本地进行更改，然后上传回资源库。但是这部分是资源库中的文件会上锁，没人访问时锁是打开的，当A客户端下载文件到本地会将文件上锁，其余客户端无法更改，A客户端更改完后再上传回资源库，锁会释放，然后其余客户端可访问。

分布式版本控制
将中央服务器复制一份到本地数据库，当中央服务器崩塌时，还能再本地数据库操作
整理后的语言：
（版本控制分为集中式和分布式两种。集中式（VSS、CVS、SVN）都是客户端从中央服务器的资源库下载文件到本地修改、再上传回资源库，它的难点在于多人并发修改同一个文件：一种做法是用加锁来解决——A 检出时把文件上锁、其他人无法更改，等 A 提交并释放锁后别人才能访问；另一种做法是允许多人同时修改，但提交时可能因为改动同一文件而产生冲突、内容失效。而分布式（如 Git）则不同，它把中央服务器的完整仓库复制一份到本地，即使中央服务器崩溃，也仍然可以在本地仓库继续操作）

版本号：
在git，用SHA-1：40位，特殊加密算法算版本号。还可以定位仓库中的文件（2+38），前两位当作文件夹，后38位当作文件名


②命令
git cat-file -p 版本号：查看Git内部某个对象的原始内容。
git内部一切东西都是对象，git对象模型

具体流程：
（1）传commit的哈希
git cat-file -p HEAD     #HEAD就是当前提交

#输出：
tree 9f1a2b3c4d5e6f...       # 指向的 tree 对象
parent 7b2a1c3d4e5f6a...     # 父提交（上一个版本）
author 张三 <z@x.com> 1690000000 +0800
committer 张三 <z@x.com> 1690000000 +0800
#这是我这次提交的说明

（2）传tree的哈希
git cat-file -p 9f1a2b3c4d
# 输出目录里的文件清单，以及每个文件指向哪个 blob：
100644 blob e6f1a2b3...  README.md
100644 blob 5c8d9e0f...  main.py
040000 tree 3c8d9e0f...  src/        # 子目录又是一个 tree
